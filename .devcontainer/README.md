## 開発までの流れ

### 注意事項

- gitのユーザー名とメールアドレスを設定していない場合、コンテナ内でgit操作ができない可能性があります。その場合は、コンテナに接続する前に事前に以下のコマンドを打つこと

```
git config user.name "ユーザー名"
git config user.email "メールアドレス"
```

- git commit -m "メッセージ名"を打つ際に、日本語入力できない方は以下のコマンドを打ってから、再度確認してください
```
export LANG=C.UTF-8
export LC_ALL=C.UTF-8
```

### 仮想環境へ接続する

- windowsの場合

  1. WSL2 を起動します（Windowsキーを押下→Ubuntuを⼊⼒）
  2. Docker を起動します︓ sudo service docker start
  3. "cd"コマンドを用いて作業⽤のフォルダに移動します
  4. `code .`を実行し、VS Code を起動します
  5. EXPLORER(左上)にてITGOAPPが開かれていることを確認します。(ここが正しくないとコンテナを開くことはできません)
  6. 左下の青いボタンを押して、「ReOpen in Container」を押下します
  7. しばらく時間が経過した後、左下に「>< Dev Container: xxx」が表示されていることを確認します

- Macの場合

    1. VSCodeを起動している場合すべて閉じます
    2. RancherDesktopを起動します
    3. VSCodeを起動します
    4. 作業用フォルダ(ITGOAPP)を開きます
    4. 左下「><」を押下する
    5. 「ReOpen in Container」を押下します
    8. しばらく経過後、先ほど押下した「><」が「>< Dev Container: xxx」に変更されていることを確認する

### 作業用ブランチを発行する

今回はgitを使用しているため、自身が作業しているブランチは分ける必要がある。そこまでの流れを記載する。
ちなみに、1つの機能が実装完了後はまた別のブランチを切ります。

1. git branch で今いる作業ブランチ名を確認する
2. すでに今回の作業ブランチにいる場合はそのまま
3. いない場合は、git checkout develop で移動する
4. git fetch で最新情報を取得
5. git pull origin develop でリモートの情報と合わせます
6. git checkout -b feature/xxx(作業ブランチ名)　でブランチを発行します。ブランチ名は他の人と被らない形でお願いします

### コンテナ内で作業をする

コンテナ内部に入れたら、実際に動作環境をしながらコードの編集をすることができます。ここでは動作環境をして、コードの編集後、git pushまでの流れを記載します

1. cd backend でバックエンドに移動する
2. npm run dev で起動する
3. 新しいターミナルを開く
4. cd frontend でフロントエンドに移動する
5. npm run dev で起動する
6. http://localhost:5173/ に接続する
7. 動作確認をする、止めたい場合は「Ctrl + C」で止めれます
8. コードの編集をする
9. 動作確認をして、自身が実装したい機能が実装できていることを確認する
10. 実装完了後、gitを用いて提出する
11. git add . で変更点を追加
12. git commit -m "メッセージ名" で自身がした作業内容を記載する
13. git push origin feature/xxx(今回、作業しているブランチ名)でリモートブランチにプッシュする

### マージリクエストを出す

現状は、feature/xxxに自分の作業内容を反映しているだけなので、developブランチに結合しても問題ないかのリクエストを出す(マージはこの段階ではしないこと!!!)

1. GitHubにアクセスする
2. 上のタブから「pull requests」を選択する
3. New Pull request を選択する
4. baseに「develop」を、compareに「作業ブランチ」を選択する
5. 下に変更内容が出てくるので、問題ないことを連絡する
6. 確認後、「Create pull request」を押下する
7. Add a titleに今回やったこと、Add a descriptionにやったことの詳細を記載する
8. 右側にレビュワーにレビューして欲しい人、Assignessに自分自身を選択する
9. 確認後、「Create pull request」を押下する

※作成後に、「Merge pull request」が押下できるが、こちらはレビュワーが確認するまではクリックしないこと!!!!

### マージする

レビュワーがマージリクエストを確認後、問題ない場合はマージリクエストを出した人に連絡する。
問題ないことと連絡が来た場合は、プルリクエスト作成者本人で「Merge pull request」を押下して、developブランチにマージする。
これで一連の流れは終了となる。これを1機能ごとに繰り返しながら、やることでアジャイル開発もどきになってくる。
